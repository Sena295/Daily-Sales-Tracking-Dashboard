## Overview

This project automates a recurring commercial reporting workflow. `daily_sales_stratos.py` reads the daily sales source files, merges them into the master workbook, applies lookup tables (ADVP, segment, booking window) and updates the pivot-driven summary reports through Excel COM automation. The standalone HTML dashboard is the **build artifact** of that pipeline: it is generated by the script and is not committed to this repository (`*.html` is git-ignored).

> **The data shown in the dashboard is illustrative and does not represent real financial figures.**

## Features

| Stage | What it does |
|:--|:--|
| **1. Análises Diárias** | Reads new daily source files, deduplicates by date, appends to the master workbook and recalculates lookup-driven columns. |
| **2. Matriz Comitê** | Updates the BRL/USD committee matrix from the refreshed daily data. |
| **3. Proj. Diária** | Updates the daily sales projection sheet, cross-checking totals against the source for data integrity. |

The generated dashboard (`Dashboard Daily Sales (In).html`) covers:

- MTD revenue vs. forecast vs. budget, with variance indicators
- Daily sales curve with day-over-day comparison
- Passenger volume and average ticket tracking
- Responsive layout, print-friendly

The script uses `pandas`, `openpyxl` and `pywin32` (Excel COM) for surgical, formula-safe updates to large shared workbooks, preserving formatting, formulas and pivot tables instead of regenerating the file from scratch.

## How to use

**Requirements:** Windows with Microsoft Excel (COM automation) and Python 3.

```bash
git clone https://github.com/Sena295/Daily-Sales-Tracking-Dashboard.git
cd Daily-Sales-Tracking-Dashboard
pip install pandas openpyxl pywin32
```

Point the script to your sales folder through the environment variable (no network path is hardcoded):

```bash
set SALES_BASE_PATH=C:\path\to\sales-folder
python daily_sales_stratos.py
```

When the pipeline finishes, open the generated `Dashboard Daily Sales (In).html` directly in any browser: no server or build step required, all data and rendering logic are self-contained in the file.

## Tech stack
